🚀 Complete Kafka & Audit-Service Integration Guide
This guide walks you through setting up Apache Kafka locally via Docker and wiring it into your Spring Boot audit-service with robust error handling and Dead-Letter Topic (DLT) support.

Part 1: Local Kafka Infrastructure (Docker)
Step 1: Start Docker Desktop
Open Docker Desktop from your Windows Start menu.

Accept any prompts (install/update WSL 2 if requested, and restart Windows if prompted).

Wait until the bottom-left corner of the window says Engine running (green).

Step 2: Verify Docker
Open PowerShell and run these commands one at a time:

PowerShell
docker --version
docker compose version
docker run hello-world
The first two should print version numbers.

The third should print Hello from Docker!.

Step 3: Create the Kafka Docker Compose File
In PowerShell, run:

PowerShell
mkdir C:\lottery-infra
cd C:\lottery-infra
notepad docker-compose.yml
Click Yes when Notepad asks to create a new file, and paste this exact configuration (ensure spaces are used for indentation, never Tabs):

YAML
services:
kafka:
image: apache/kafka:4.0.0
container_name: lottery-kafka
restart: unless-stopped
ports:
- “9092:9092”
Save with Ctrl + S and close Notepad.

Step 4: Start Kafka
Run the following command to start the container in the background:

PowerShell
docker compose up -d
Check that it is running:

PowerShell
docker compose ps
docker compose logs kafka
(Look near the end of the logs for a line stating that the Kafka server has started).

Step 5: Create the Required Topics
Run each command on a single line:

PowerShell
docker exec lottery-kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --topic audit-events --partitions 3 --replication-factor 1
docker exec lottery-kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --topic audit-events.DLT --partitions 1 --replication-factor 1
docker exec lottery-kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
Each create command should output Created topic …, and the list command should display both topics.

Step 6: Test Messaging (Two Terminals)
Window 1 (Reader):

PowerShell
docker exec -it lottery-kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic audit-events --from-beginning
Window 2 (Sender):

PowerShell
docker exec -it lottery-kafka /opt/kafka/bin/kafka-console-producer.sh --bootstrap-server localhost:9092 --topic audit-events
Type hello and press Enter in Window 2. It should instantly appear in Window 1. Press Ctrl + C in both windows when done.

🛠️ Everyday Kafka Commands
What you want Command (run in C:\lottery-infra)
Stop Kafka docker compose stop
Start Kafka again docker compose start
Check status docker compose ps
Remove completely (deletes messages) docker compose down
Note: Docker Desktop must be running whenever you use Kafka. After a reboot, open Docker Desktop first; restart: unless-stopped will handle the rest.

Step 3: Create the Listener
Create com.lottery.audit.kafka.AuditEventListener.java:

Java
package com.lottery.audit.kafka;

import com.lottery.audit.dto.AuditEventRequest;
import com.lottery.audit.exception.DuplicateResourceException;
import com.lottery.audit.service.AuditService;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.kafka.annotation.KafkaListener;
import org.springframework.stereotype.Component;
import tools.jackson.databind.DeserializationFeature;
import tools.jackson.databind.json.JsonMapper;

@Component
public class AuditEventListener {

private static final Logger log = LoggerFactory.getLogger(AuditEventListener.class);

private static final JsonMapper MAPPER = JsonMapper.builder()
        .disable(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES)
        .build();

private final AuditService auditService;

public AuditEventListener(AuditService auditService) {
    this.auditService = auditService;
}

@KafkaListener(topics = "${audit.kafka.topic:audit-events}")
public void onMessage(String payload) {
    AuditEventRequest request = MAPPER.readValue(payload, AuditEventRequest.class);

    if (isBlank(request.eventId()) || isBlank(request.serviceName())
            || isBlank(request.action())) {
        throw new IllegalArgumentException(
                "eventId, serviceName and action are required");
    }

    try {
        auditService.record(request);
    } catch (DuplicateResourceException e) {
        log.debug("Audit event {} was already recorded", request.eventId());
    }
}

private static boolean isBlank(String value) {
    return value == null || value.isBlank();
}

}
Step 4: Configure Error Handling & DLT
Create com.lottery.audit.kafka.KafkaErrorConfig.java:

Java
package com.lottery.audit.kafka;

import org.apache.kafka.common.TopicPartition;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.kafka.core.KafkaTemplate;
import org.springframework.kafka.listener.DeadLetterPublishingRecoverer;
import org.springframework.kafka.listener.DefaultErrorHandler;
import org.springframework.util.backoff.FixedBackOff;

@Configuration
public class KafkaErrorConfig {

@Bean
DefaultErrorHandler kafkaErrorHandler(KafkaTemplate<String, String> template) {
    DeadLetterPublishingRecoverer recoverer = new DeadLetterPublishingRecoverer(template,
            (record, ex) -> new TopicPartition(record.topic() + ".DLT", 0));
    DefaultErrorHandler handler =
            new DefaultErrorHandler(recoverer, new FixedBackOff(1000L, 3L));
    
    // Non-retryable exceptions go straight to DLT
    handler.addNotRetryableExceptions(IllegalArgumentException.class);
    return handler;
}

}

🔍 Troubleshooting Reference
Symptom Likely Cause Solution
No Kafka lines in logs Starter not on classpath / Maven not reloaded. Verify pom.xml and reload Maven.
Connection to node -1 failed Kafka isn’t running or compose file down. Check docker compose ps and start cluster.
JsonParseException in logs Pasted line broke in terminal. Copy and paste the JSON as a single continuous line.
DLT topics empty DLT topic not created or error handler bean missing. Re-run Step 5 topic creation commands.
